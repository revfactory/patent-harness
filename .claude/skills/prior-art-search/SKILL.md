# 선행기술 검색과 서지 검증

이 스킬은 prior-art-searcher와 citation-verifier가 따르는 절차다. 검색은 찾는 일, 검증은 이미 적힌 기재가 원문과 맞는지 대조하는 일이다. 두 일 모두 원문을 직접 연 기록을 남기는 것이 핵심이다. 특허 판단은 문헌 번호 하나, 날짜 하루 차이로 결론이 바뀌기 때문이다.

## 도구

| 도구 | 용도 | 사용법 |
| --- | --- | --- |
| `scripts/gpatents_fetch.py` | Google Patents 원문에서 제목, 출원인, 우선일·출원일·공개일, 법적 상태, 예상 만료일, 청구항 1, 초록, CPC, 피인용 수를 JSON으로 가져온다 | `python3 -I .claude/skills/prior-art-search/scripts/gpatents_fetch.py US5960411A US6285999B1 --out _workspace/{case}/01_raw/batch1.json` |
| `scripts/extract_patent_refs.py` | PDF·Markdown 보고서에서 특허 번호와 Google Patents 링크를 뽑는다. PDF 링크 주석도 읽는다 | `python3 -I .claude/skills/prior-art-search/scripts/extract_patent_refs.py report.pdf --out refs.json --text-out source.txt` |
| WebFetch | 스크립트가 못 읽는 페이지(Espacenet, 특허청 공보, 비특허 문헌) | URL을 직접 연다 |
| WebSearch | 키워드 검색, 비특허 문헌, 제품·논문 찾기 | 검색 결과 요약만으로 판정하지 않는다 |

- 스크립트는 프로젝트 폴더 아래 경로로만 출력한다. `/tmp`를 쓰지 않는다.
- 스크립트는 번호 하나에 2초 쉬고 다음 번호를 가져온다. 50건이면 2분 정도 걸린다.
- 여러 에이전트가 같은 IP에서 동시에 Google Patents를 읽으면 503 차단 페이지가 30~90분 이어진다(2026-10-25 실제 사건에서 에이전트 7명 동시 실행 중 3회 발생). 동시에 도는 검색·검증 에이전트가 3명 이상이면 `--sleep 4` 이상을 쓴다. 503이 나오면 짧은 간격으로 재시도하지 말고 Espacenet·J-PlatPat으로 바꾸거나 미열람으로 남긴다. 반복 재시도는 차단 시간을 늘리고 권한 검사에서 우회 시도로 거부될 수 있다.
- KIPRIS, J-PlatPat은 직접 접속이 막힐 수 있다. 막히면 Google Patents, Espacenet(`https://worldwide.espacenet.com/patent/search?q=pn%3D{번호}`)으로 대체하고 대체 사실을 기록한다.
- J-PlatPat은 curl로는 막혀도 브라우저 자동화 도구가 있으면 열리는 경우가 있다. 일본 출원의 거절이유통지서, 거절사정, 심판 청구, 신규성 상실 예외 증명서 제출 같은 경과 정보는 Google에 없으므로, 존속·거절 여부가 판단을 바꾸는 일본 문헌은 J-PlatPat 경과정보를 우선 시도한다.

데이터베이스별 번호 형식, 분류코드 체계, 검색식 작성 예는 `references/databases.md`에 있다. 번호 형식 때문에 404가 나거나 분류 검색식을 짤 때 읽는다.

## A. 선행기술 검색 절차

1. **대상 구성 분해**: 의뢰받은 발명을 구성 요소 C1, C2 … 로 나눈다. 오케스트레이터가 나눠 주었으면 그대로 쓴다. 검색은 "모든 구성을 가진 문헌"이 아니라 "구성 하나 이상을 가진 문헌"을 찾는 일이다. 진보성은 여러 문헌의 결합으로 판단하기 때문이다.
2. **검색 기준 확인**: 배정받은 기준 하나(키워드 / 분류 / 출원인 / 인용 추적 / 특정 문헌 확인)에 집중한다.
3. **검색식 작성**: 동의어와 각국 표현을 함께 쓴다. 예: 밑창 = 靴底, ソール, 鞋底, outsole, sole. 분류는 IPC 메인그룹과 서브그룹을 둘 다 써 본다.
4. **결과 선별**: 제목·초록으로 1차 선별하고, 남은 문헌은 원문(청구항, 도면, 실시예)을 연다.
5. **기록**: 문헌마다 다음을 남긴다.
   - 번호, 제목, 출원인, 우선일, 법적 상태(Google 표시값 그대로)
   - 관련도 X / Y / A와 대응 구성(C 번호)
   - 기재 위치(청구항 번호, 문단 번호, 도면 번호)
   - `opened_fulltext`: 원문을 열었는지 여부
6. **검색 이력**: 데이터베이스, 검색식, 결과 건수, 검토 건수를 표로 남긴다. 결과 건수를 남기지 않으면 검색 범위가 충분했는지 아무도 판단할 수 없다.
7. **인용 추적**: X·Y 문헌은 인용 문헌(backward)과 피인용 문헌(forward)을 한 단계 더 확인한다. Google Patents 페이지의 "Cited By", "Similar Documents"를 쓴다.

### 비특허 문헌

논문, 제품 카탈로그, 보도자료, 학회 발표도 선행기술이다. 날짜(공개일)를 반드시 기록한다. 공개일이 불명확하면 "공개일 미확인"으로 표시한다. 공개일을 모르는 문헌은 선행기술로 쓸 수 없기 때문이다.

## B. 서지 검증 절차(보고서 대조)

1. **번호 목록 확보**: 보고서가 PDF면 `extract_patent_refs.py`로 번호와 링크를 뽑는다. 링크 대상 번호와 화면에 보이는 번호가 다르면(예: 화면은 등록번호 JP7123456B2, 링크는 공개번호 JP2019123456A) 같은 출원의 공개·등록 관계인지 확인한다. 다른 출원이면 보고서 오류다.
2. **원문 가져오기**: 배정받은 번호를 한 번에 스크립트로 가져와 `_workspace/{case}/01_raw/`에 저장한다.
3. **항목별 대조**: 보고서 기재를 다음 기준으로 대조한다.

| 항목 | 대조 기준 | 흔한 오류 |
| --- | --- | --- |
| 국가 | 번호의 국가코드 | 패밀리 문헌의 국가를 섞어 적음 |
| 출원인 | 원 출원인(assignee_original). 현재 권리자가 다르면 함께 적음 | 공동 출원인 누락, 사명 변경(松下電器産業 → パナソニック) |
| 연도 | 보고서가 "출원"이면 filing_date, "우선"이면 priority_date | 공개일을 출원일로 적음 |
| 법적 상태 | Google 표시값, events, `legal_events`(페이지 아래 법적 이벤트 표). 표시값이 상식과 어긋나면 `legal_events`에서 거절사정(A02)·말소(LAPS, CF01)·등록(R150) 기록을 먼저 찾고, 없을 때만 `표시값 의심` | 오래된 일본 출원이 `Pending`으로 표시되지만 `legal_events`에 A02가 있음 |
| 만료 예정 | anticipated_expiration | 연차료 미납 소멸을 만료로 적음 |
| 핵심 내용 | 청구항 1 + 초록. 실시예에만 있는 내용인지 구분 | 실시예 내용을 권리 범위처럼 적음 |

4. **판정**: 항목마다 `일치`, `불일치`, `확인 불가`. 문헌 전체 판정은 모든 항목이 일치하면 `일치`, 핵심 내용이나 번호가 틀리면 `불일치`, 그 밖의 항목만 틀리면 `부분 불일치`.
5. **바로잡을 값**: 불일치 항목은 원문 값과 근거(필드명, URL)를 적는다.

### 법적 상태 해석

- Google Patents의 상태는 Google이 추정한 값이다. "Expired - Lifetime"(존속기간 만료), "Expired - Fee Related"(연차료 미납 소멸), "Ceased"(소멸), "Withdrawn"(취하·간주취하), "Abandoned"(포기), "Active"(존속), "Pending"(심사 중)을 구분해 그대로 옮긴다.
- 특허 존속기간은 출원일부터 20년, 한국·일본 실용신안은 출원일부터 10년(일본 1994~2005년 출원 실용신안은 6년)이다. 이 기간이 지났는데 `Active`나 `Pending`이면 `legal_events`를 확인한 뒤에도 근거가 없을 때 `표시값 의심`으로 적는다. 스크립트 결과 `events`는 페이지 위쪽 타임라인만 담으므로 거절·말소 기록이 빠질 수 있다.
- 존속 여부가 판단에 결정적이면(자유실시 판단 등) 각국 특허청 원부 확인이 필요하다고 남긴다.

## 출력

- 워크플로에서 호출되면 오케스트레이터가 넘긴 `schema`로 반환한다.
- 단독 실행이면 `_workspace/{case}/01_{agent}_{artifact}.md`에 표로 쓴다.
- 서지 정보는 스크립트 결과를 그대로 옮기고, 사람이 고쳐 쓴 값에는 이유를 붙인다.
