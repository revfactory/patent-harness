# 명세서와 도면 작성

spec-writer와 drawing-designer가 따르는 절차다. 명세서는 청구항의 근거 문서다. 청구항에 쓴 말이 명세서에 같은 말로, 실시할 수 있을 만큼 구체적으로 있어야 등록되고, 심사 중 보정도 명세서에 적힌 범위 안에서만 할 수 있다.

## 1. 작성 순서

1. **용어표 만들기**: 청구항의 모든 구성 명칭을 표로 뽑는다. 명세서 전체에서 이 이름만 쓴다.
2. **도면 부호 받기**: drawing-designer의 부호표(`05_drawing-designer_figures.md`)를 기준으로 쓴다. 부호표에 없는 구성이 필요하면 리더에게 도면 추가를 요청한다.
3. **서식 순서대로 작성**: `references/spec-template.md`의 양식을 그대로 따른다.
4. **청구항 대응 확인**: 마지막에 "청구항 구성 → 명세서 문단 번호" 대응표를 만들어 파일 끝에 붙인다. formality-checker가 이 표로 검사한다.

## 2. 절별 작성 원칙

| 절 | 원칙 | 이유 |
| --- | --- | --- |
| 기술분야 | 한두 문장. 발명이 속한 분야를 넓게 | 지나치게 좁으면 범위 해석이 좁아진다 |
| 배경기술 | 검증 원장의 문헌을 번호로 인용하고 한계를 사실대로 적는다 | 과장은 의견서 단계에서 불리한 기재가 된다 |
| 해결하려는 과제 | 배경기술의 한계와 1:1로 대응 | 과제-해결-효과의 연결이 진보성 논리다 |
| 과제의 해결 수단 | 독립항을 풀어 쓰고, 종속항마다 "일 실시예에 따르면"으로 한 문단씩 | 보정 근거 확보 |
| 발명의 효과 | 구성에서 효과가 나오는 이유를 함께 | 이유 없는 효과는 참작되지 않는다 |
| 구체적인 내용 | 구성별 재료 범위(넓은 → 바람직한 → 가장 바람직한), 형상 변형, 제조 공정, 사용 순서, 실시예·비교예, 측정 방법 | 실시 가능 요건과 보정 근거 |
| 측정 방법 | 시편, 장비, 조건, 계산식, 판정 기준을 재현 가능하게 | 수치 한정 청구항의 명확성 |
| 실시예 데이터 | 시험 결과가 없으면 `[시험 데이터 삽입: 시험 T번호]` 표시 | 지어낸 데이터는 출원 무효 사유가 될 수 있다 |

- 문단 번호는 `[0001]`부터 연속으로 붙인다.
- "본 발명은 ~에 한정되지 않는다"는 문장을 남발하지 않는다. 변형례를 구체적으로 적는 편이 범위 해석에 실제로 도움이 된다.
- 비유 표현과 번역투를 쓰지 않는다. 구성 명칭은 청구항과 같게 쓴다.
- 문단 번호가 다시 매겨지면 다른 문서(청구항 메모, 시험 계획, 도면 문서)의 문단 인용은 번호를 일정하게 더하거나 빼지 말고 인용마다 내용을 대조해 고친다. 내용이 새 문단으로 옮겨 가거나 본문에서 작업 메모로 빠진 경우가 있다(실제 사건의 시험 계획 인용 84회 중 4회).
- 실시예를 나눌 때 뒤 번호를 다시 매기지 않으려면 '실시예 17-1'처럼 가지 번호를 쓰고, 같은 숫자 꼴의 소제목은 본문에서 항상 '절'을 붙여 인용한다.

## 3. 도면

drawing-designer가 따르는 규칙이다.

- 도면 목록: 발명 유형에 맞춰 고른다. 구조물이면 전체 사시도, 단면도(층 구조), 평면도(영역 구획), 작동 단계도, 제조 공정 순서도, 시험 결과 그래프를 기본 후보로 둔다. 방법·소프트웨어 발명이면 순서도와 블록도가 중심이다.
- 모든 청구항 구성이 적어도 한 도면에 나와야 한다.
- 부호 체계: 상위 구성 100 단위, 하위 구성 10 단위, 세부 1 단위. 예: 밑창 100 → 밑창 본체 110, 돌기 120 / 갑피 200 → 토캡 210.
- 흑백 선도. 층 구별은 해칭 패턴으로 한다. 색상에 의미를 담지 않는다.
- SVG 개략도는 viewBox를 지정하고, 부호는 지시선과 숫자로 표시한다. 글자 설명은 넣지 않는다(특허 도면은 부호만 쓴다).
- 그래프는 데이터가 없으면 축 이름과 단위만 그린다.

도면 파일의 첫머리 주석에 "출원용 최종 도면이 아니라 도면 업체에 넘길 기준안"이라고 적는다.

## 4. 출력

- 명세서: `_workspace/{case}/05_spec-writer_specification.md`
- 도면 구성안: `_workspace/{case}/05_drawing-designer_figures.md` (도면 목록, 도면의 간단한 설명 문장, 부호표)
- 도면 개략도: `_workspace/{case}/05_drawing-designer_fig{n}.svg`
